GraspSort
Vision-Guided Pick-and-Place Sorting with YOLO, RGB-D, MoveIt 2 and ROS 2


One-line pitch: a simulated robot arm looks at a cluttered table with an RGB-D camera, detects objects with YOLO,
estimates each object's 3D pose, and picks and places every object into the bin for its class, using collision-aware motion
planning in MoveIt 2.
Purpose of this document: the architecture reference for a second portfolio project, built with the same Claude Code
workflow as SemNav. It deliberately covers a skill area SemNav did not: manipulation (kinematics, motion planning, grasping,
planning scenes).


1. Why this project
• New skill area: SemNav proved perception, fusion and mobile navigation. GraspSort adds manipulation: inverse
   kinematics, Cartesian paths, collision objects, attach/detach, grasp candidates.
• Reuse where it is cheap: the YOLO ONNX Runtime node, the CycloneDDS + sysctl setup, the CLAUDE.md protocol and
   the ground-truth evaluation style carry over almost unchanged.
• Measurable: pick success rate, 3D pose error vs ground truth, planning time and cycle time on randomised layouts, so the
   README has real numbers.
• Strong demo: an arm sorting objects into bins reads instantly in a 30-second video.
• Scope control: fixed overhead camera (no hand-eye loop), top-down grasps, rigid simple objects, simulation only. No
   learned grasping, no dexterous hands.

Reading the diagram: orange "C++" tags mark code you write. Blue is MoveIt and the planning scene. Perception produces
3D object poses; the scene manager turns them into collision objects; the sort task node asks the grasp planner for
candidates and MoveIt for collision-free trajectories, then executes them through ros2_control.

Data flow for one object
• The detector publishes 2D boxes for the latest colour frame (newest-frame buffer + worker thread, as in SemNav).
• The localizer takes the matching depth image, computes a robust depth inside the central part of each box, back-projects
   with the camera intrinsics, transforms to the world frame via TF and estimates footprint size and yaw from the depth mask.
• The scene manager adds or updates each object as a MoveIt collision object (cylinder or box) and keeps the table and
   bins as fixed objects.
• The sort task node picks the next object, gets ranked grasp candidates, and executes: pre-grasp -> straight-line approach
   -> close gripper -> attach -> lift -> move above the class bin -> release -> detach -> retreat.
• After each place, the object is removed from the planning scene and the camera view is re-checked before the next pick.

7. Node specifications

7.1 object_detector_node (C++, reused)
• Copy from SemNav with its tests: letterbox, decode [1,84,8400], NMS, worker thread, /metrics p50/p95.
• Change only the class_filter default to the GraspSort classes chosen in Phase 0, and the image topic name.

7.2 object_localizer_node (C++)
 Aspect                Design

 Depth sampling        Take depth pixels in the central 50% of the box; reject zeros/NaN; use the 20th percentile (nearest surface) rather than
                       the median, so table pixels around a thin object do not pull the estimate (lesson from SemNav D-22).

 3D point              Back-project the box centre with fx, fy, cx, cy from CameraInfo at that depth; push in by half the estimated object depth to
                       approximate the centre.

 Footprint and yaw     Segment pixels within +/- 2 cm of the object depth inside the box, project them to the table plane, cv::minAreaRect for
                       size and yaw (yaw ignored for cylinders).

 Height                Table plane height is known (parameter or fitted once); object height = table height - top surface.

 Stability             Objects are static: average over N frames, publish when the standard deviation is under a threshold. Track ids by nearest
                       neighbour in 3D.

 Frames                Read frame_id from the image header; TF at the image stamp; fail loudly if TF fails (SemNav D-05 rule).

 Tests                 GoogleTests for back-projection, percentile sampling with table pixels present, minAreaRect yaw, and stability gating.


7.3 scene_manager_node (C++)
• Adds the table and bins once at start-up as fixed collision objects (from parameters matching the world file).
• Adds or updates each perceived object as a cylinder or box; removes objects that are no longer seen; never adds objects
   from the world file directly.
• Supports attach/detach of the held object to the gripper link so MoveIt plans transport moves with the object in hand.
• Exposes a small service to freeze the scene during a pick, so a mid-motion perception update cannot move the target.

7.4 grasp_planner (ROS-free C++ library)
 Aspect                Design

 Candidates            Top-down grasps only. For boxes: yaw aligned with the short side, plus 180 deg. For cylinders: 8 yaws around the axis.
                       Grasp height from object height (fingers at 60% of height).

 Filtering             Reject candidates whose gripper opening is too small for the object width; reject if fingers would hit neighbouring objects
                       (2D footprint check).

 Ranking               Prefer yaw closest to the current wrist yaw (shorter motions) and largest clearance to neighbours.

 Tests                 Box and cylinder candidates, width rejection, neighbour collision rejection, ranking order.


7.5 sort_task_node (C++, MoveGroupInterface)
 Stage                 Implementation

 Order                 Pick the object closest to the arm base first that is reachable (IK check) and not blocked.

 Pre-grasp             Pose 10 cm above the grasp with gripper open; plan with OMPL; try the next candidate if planning fails.

 Approach / retreat    Straight-line Cartesian moves (computeCartesianPath or Pilz LIN), requiring at least 95% of the path.

 Grasp                 Close the gripper with an effort limit, call attach (Gazebo) and attachObject (MoveIt).

 Transport and         Move above the bin of the object's class (bin_assignment.hpp), lower, open, detach, retreat.
 place

 Recovery              Up to 2 retries per object with the next grasp candidate; on failure report the reason in the action result and continue with
                       the next object.

 Feedback              Publish stage and object in action feedback; log per-stage timings for the evaluation.


7.6 Grasp attach plugin (C++ Gazebo plugin, or community link attacher)
• Creates a fixed joint between the gripper finger link and the object model on /attach, removes it on /detach.

11. Claude Code workflow

CLAUDE.md (start from the SemNav one, change only these parts)
 # GraspSort rules
 Source of truth: docs/architecture.txt. Implement it; do not redesign it.
 Stack: ROS 2 Humble, Ubuntu 22.04, Gazebo (per D-01), MoveIt 2, C++17, ament_cmake.
 Middleware: RMW_IMPLEMENTATION=rmw_cyclonedds_cpp in every launch file.
 Pure logic in ROS-free headers with GoogleTests. All tunables are parameters.
 Objects are never added to the planning scene from world files; only from perception.
 Every investigation has a time box; record findings and fallbacks in docs/DECISIONS.md.
 Never run sudo; give me the exact command. Single branch main; commit per green slice; I push.
 End every task with: files changed | commands + results | tests | issues | deviations | what I verify.

Prompt style that worked in SemNav
• One phase per session, /clear between phases, short prompts that name the architecture section to follow.
• Independent work in parallel subagents (for example messages, ROS-free libraries and launch files), integration by the
     main agent.
• Always end with an objective check: tests, topic rates, ground-truth error, or action results, never "looks right".
• Hard stops on debugging, with the fallback written down before starting.

12. Interview angle
• Story: "After a navigation project, I wanted to learn manipulation, so I built a vision-guided sorting arm and measured its
   success rate under increasing clutter."
• Be ready to explain: why top-down grasps, how depth becomes a 3D pose, why percentile depth instead of median, how
   MoveIt uses collision objects, why attach in Gazebo, and what the failure breakdown told you.
• Stretch goals that add depth: hand-eye calibration with an ArUco marker, MoveIt Task Constructor, a wrist camera for a
   closer second look, or a pose-estimation upgrade for non-upright objects.
